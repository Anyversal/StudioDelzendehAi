# پاک‌سازی امن فضای ذخیره‌سازی

این راهنما فقط فایل‌های تولیدشده و cache محلی را هدف می‌گیرد. کد منبع، تصاویر مورد استفادهٔ رابط، فایل‌های تنظیمات لازم و تاریخچهٔ Git را حذف یا بازنویسی نمی‌کند.

## نتیجهٔ بررسی مخزن

در snapshot بررسی‌شده، سه تصویر در مجموع حدود ۳٫۳ مگابایت‌اند و همگی در کامپوننت‌های برنامه ارجاع دارند؛ بنابراین حذفشان می‌تواند ظاهر یا عملکرد رابط را خراب کند. فایل `node_modules/`، خروجی build و cacheهای محلی در فهرست فایل‌های Git دیده نشده‌اند؛ `.gitignore` مانع اضافه‌شدن آن‌ها در commitهای آینده می‌شود، اما فایل‌هایی را که قبلاً track شده‌اند از تاریخچه پاک نمی‌کند.

## پاک‌سازی محلی و برگشت‌پذیر

پس از clone در رایانهٔ مالک، از ریشهٔ پروژه اجرا کنید:

```bash
npm run clean
```

این دستور طبق `package.json` خروجی `dist` و `server.js` را حذف می‌کند. اگر `server.js` را دستی ایجاد و نگهداری کرده‌اید، قبل از اجرا از آن نسخهٔ پشتیبان بگیرید. برای حذف dependencyهای قابل‌بازسازی نیز (با توجه به فضای محلی و نیاز پروژه):

```bash
rm -rf node_modules
```

در Windows PowerShell:

```powershell
Remove-Item -Recurse -Force node_modules -ErrorAction SilentlyContinue
```

`node_modules` را بعداً با `npm install` دوباره بسازید. این حذف، فضای دیسک رایانهٔ اجراکننده را آزاد می‌کند؛ فضای repository روی GitHub را کاهش نمی‌دهد.

## کاهش اندازهٔ assetها

تصاویر فعلی استفاده می‌شوند، پس در این تغییر حذف نشده‌اند. برای کاهش حجم آن‌ها، فایل‌های WebP/AVIF بهینه را در یک commit جداگانه اضافه کنید، importها را به فایل‌های جدید تغییر دهید و build و بررسی بصری را انجام دهید. فایل قدیمی را تنها پس از تأیید build، نمایش صفحه‌ها و مقایسهٔ اندازه حذف کنید. این محیط نمی‌تواند فایل باینری را تبدیل یا تست رندر واقعی انجام دهد؛ بنابراین فشرده‌سازی تصویر در این commit اعمال نشده است.

## تاریخچهٔ Git و فایل‌های track‌شده

`.gitignore` فقط از track شدن فایل‌های جدید جلوگیری می‌کند. پاک‌کردن فایل track‌شده یا بازنویسی تاریخچه می‌تواند cloneها، tagها، شاخه‌ها و نسخه‌های منتشرشده را تحت‌تأثیر قرار دهد و در این پاک‌سازی انجام نشده است. ابتدا با clone محلی، ابزار اندازه‌گیری Git و بررسی usage، فایل‌های حجیم و سابقهٔ استفاده را شناسایی کنید. بازنویسی تاریخچه یا حذف فایل‌های فعال فقط در تغییر جداگانه، پس از backup و تأیید مالک انجام شود.

## بررسی پس از پاک‌سازی

1. `npm install`
2. `npm run lint`
3. `npm run build`
4. صفحات استفاده‌کننده از assetهای تصویری را در preview بازبینی کنید.
5. مطمئن شوید diff فقط شامل فایل‌های cache/output مورد انتظار است.
